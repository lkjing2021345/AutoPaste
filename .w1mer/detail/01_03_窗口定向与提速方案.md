# 03 目标窗口定向 + 输入提速 — 实施计划

> 读者：任务 03 的 implementer。
> 基线：commit `9c6c9a3`（任务 01 完成后的 `autopaste.py`，951 行，62 个 unittest）。
> 前置：任务 02（`Backend` 抽象）先合入。本文所有"在 `X11Backend` 上加方法"的位置，
> 在 02 合入后按**函数名**定位，不要按本文行号硬搬。
> 一句话目标：**在不放宽任何安全闸门的前提下，让"敲到哪里"可控（`--window`）、
> 让大段文本可用（`--paste-mode`）、让 X11 逐字符注入的固定开销降下来（批量 flush）。**

## 0. 结论摘要（先看这 7 条）

1. **窗口枚举以 EWMH 优先、XQueryTree 兜底**：读 root 的 `_NET_CLIENT_LIST`
   （映射顺序）与 `_NET_CLIENT_LIST_STACKING`（叠放顺序，最后=最上层）；两者都没有时
   才递归 `XQueryTree(root)`。客户端窗口用 `XGetWindowAttributes` 过滤
   `override_redirect` / 非 viewable（兜底路径）。
2. **标题优先 `_NET_WM_NAME`（UTF8_STRING）**，回退 `XFetchName`/`WM_NAME`
   （可能非 UTF-8：先 utf-8，失败用 latin-1，`errors="replace"`）。`WM_CLASS`
   复用现有 `XGetClassHint`；`_NET_WM_PID` / `_NET_WM_DESKTOP` 读 32 位属性。
3. **匹配语义：默认大小写不敏感子串，匹配 class / instance / title 任一**；
   前缀 `class:` `title:` `id:` `pid:` `re:`。`re:` 是唯一正则入口（显式 opt-in）。
   `--list-windows` 输出 **6 列 TSV**（id / class / pid / desktop / active / title，
   title 在最后），stdout 是 tty 时才打表头，方便管道。
4. **同名多窗口：先选"当前激活且匹配"的那个；否则 tty 下打印编号让用户选；
   非 tty 直接报错退出 2**（列出候选）。理由：定向窗口是安全功能，"猜"比"报错"危险。
5. **激活用 `_NET_ACTIVE_WINDOW` ClientMessage，失败再 `XRaiseWindow`+`XSetInputFocus` 兜底；
   之后轮询 `XGetInputFocus`（0.6s / 50ms）确认焦点落在目标或其后代**。失败退出 2，
   并明确提示是 WM 的焦点抢占防护。**Xlib 默认错误处理器会 `exit(1)`，必须临时装
   `XSetErrorHandler` 吞掉 BadWindow/BadMatch**（见 §6.3，这是本任务最容易翻车的点）。
6. **paste-mode 的安全核心是"备份不成就拒绝"**：读原剪贴板（文本、≤4 MiB）→ 写入 →
   等 80ms 所有权建立 → 发 Ctrl+V（终端自动改 Ctrl+Shift+V）→ 等目标取走（默认按体积
   0.5–3s）→ 恢复。备份失败/非文本/超时 → 默认退出 2，除非显式 `--no-restore-clipboard`。
   绝不静默覆盖用户剪贴板。
7. **提速的真实收益要诚实**：默认 `-d 0.008` 时瓶颈是 8ms 间隔，批量只去掉 flush 开销
   （约 +1–5%）；`-d 0` 时批量 + 服务端 delay 才是数量级提升（约 5–20×）。
   **大文本真正的"提速"是 `--paste-mode`**（1 MiB 约 0.5–1s，逐字符默认要 2.3 小时）。

## 1. 与任务 02 的接口契约（必须先对齐）

任务 02 已确定：`Typer` 是 façade，`X11Backend` 持有 `dpy`，`focus_info()` / `capabilities()`

```python
# Backend 基类（02 已建）新增，全部有安全默认值，wtype/ydotool 不需要改动：

    def list_windows(self) -> list["WindowInfo"]:
```

- 任务 02 的 `target_label(typer)`/`multiline_risk(typer, text)` 继续复用；03 只在
  `countdown()` 上加一个可选 `label` 参数，避免"定向窗口"和"当前焦点"两份文案打架。

## 2. A. `--window <pattern>` 定向

### 2.1 数据模型

```python
@dataclasses.dataclass(frozen=True)
class WindowInfo:
    xid: int
    cls: str = ""          # WM_CLASS 第二段（res_class）
    instance: str = ""     # WM_CLASS 第一段（res_name）
    title: str = ""        # _NET_WM_NAME 优先，WM_NAME 兜底
    pid: int | None = None
    desktop: int | None = None   # 0xFFFFFFFF 表示"所有桌面"→ None
```

`focused_window()` 的现有返回 dict 保持不动（02 已把它接到 `focus_info()`），
`WindowInfo` 只用于枚举/定向；两者共用底层的 `_window_info_raw()` 读取逻辑。

### 2.2 枚举来源：EWMH 优先，XQueryTree 兜底

| 来源 | 顺序语义 | 取舍 |
|---|---|---|
| `_NET_CLIENT_LIST`（root, XA_WINDOW） | 映射顺序，不是叠放顺序 | **首选**：只含真正的顶层客户端，不含 WM 边框/内部窗口 |
| `_NET_CLIENT_LIST_STACKING` | 从底到顶，最后一个最上层 | 用来给候选排序（"最近/最上面"优先）和 `--list-windows` 输出顺序 |
| `XQueryTree(root)` 递归 | 树顺序 | 兜底：dwm/twm/部分轻量 WM 没有 EWMH。过滤 `override_redirect=False` 且 `map_state=IsViewable(2)`，并至少要有 `WM_CLASS` 或标题 |

实现要点：

```python
def _atom(dpy, name: str, only_if_exists=False) -> int:
    return x11.XInternAtom(dpy, name.encode(), bool(only_if_exists))

def _prop32(dpy, win, prop, req_type) -> list[int] | None:
    # XGetWindowProperty(..., long_length=max_bytes//4, delete=False,
    #                    req_type=req_type, ...)
    # format==32 时把返回指针 cast 成 POINTER(c_ulong)，取 nitems 个；
    # 注意 LP64 下每个 32 位属性项占 8 字节（Xlib 返回 long 数组），
    # 不要按 nitems*4 去 string_at。读完一定 XFree。
```

- `_NET_CLIENT_LIST` 缺失/为空 → 递归兜底。两者都拿到时，用 stacking 的顺序给
  client list 排序；stacking 里没有的窗口放最前（`order=-1`）。
- 兜底递归里"有 WM_CLASS/标题的子窗口"才是客户端；WM 边框窗口没有这些属性，天然跳过。
  仍要 `override_redirect` 过滤（菜单/提示框）。
- 跳过明显不是输入目标的 `_NET_WM_WINDOW_TYPE`：`_NET_WM_WINDOW_TYPE_DESKTOP`、
  `_DOCK`、`_TOOLTIP`、`_MENU`、`_DROPDOWN_MENU`、`_POPUP_MENU`。`DIALOG`/`UTILITY`
  **保留**（用户可能就是要填对话框）。
- 图标化窗口在 `_NET_CLIENT_LIST` 里仍在（`map_state` 可能是 Unmapped），**不要用
  map_state 过滤 EWMH 列表**，否则 `--window` 找不到最小化的窗口；激活时 WM 会还原。
  只有 XQueryTree 兜底路径才要求 viewable。
- 每个属性读取设上限（title 8 KiB、class 4 KiB、PID/desktop 只取第 1 项），避免恶意
  超长属性拖死程序。

### 2.3 标题与编码

1. `_NET_WM_NAME`（`req_type=UTF8_STRING`）→ `bytes.decode("utf-8", "replace")`。
2. 没有 → `XFetchName`（现有实现）→ 现有 `_decode()`（utf-8 "replace"）。
   `WM_NAME` 在旧程序里可能是 ISO-8859-1：实现时先严格 `raw.decode("utf-8")`，
   捕获 `UnicodeDecodeError` 再 `latin-1`，最后才 `replace`；不要只依赖现有 `_decode()`。
3. `WM_CLASS`：`XGetClassHint`，`ctypes.string_at` 后 `utf-8/replace`（现有实现）；
   两个字段都必须 `XFree`。
4. `_NET_WM_PID`：CARDINAL；0 或缺失 → `None`。
5. `_NET_WM_DESKTOP`：0xFFFFFFFF → `None`（所有桌面）。

### 2.4 匹配语义

```python
def parse_pattern(pat: str) -> tuple[str, str]:
    for prefix in ("class:", "title:", "pid:", "id:", "re:"):
        if pat.startswith(prefix):
            return prefix[:-1], pat[len(prefix):]
    return "any", pat
```

| 模式 | 匹配对象 | 规则 |
|---|---|---|
| `hello`（无前缀） | `cls` / `instance` / `title` | `casefold()` 子串 |
| `class:kitty` | `cls` + `instance` | 子串、大小写不敏感 |
| `title:文档` | `title` | 子串、大小写不敏感 |
| `id:0x03a00007` / `id:123` | XID | 精确（`int(s, 0)`） |
| `pid:1234` | `_NET_WM_PID` | 精确；`pid:` 后不是整数 → 退出 1 |
| `re:^(\[)?nvim` | `cls instance title` 拼串 | `re.search(..., re.IGNORECASE)` |

- **默认不做正则**：子串是 95% 的用法，且不会让用户被正则元字符坑到。
  需要正则必须显式 `re:`；`(?-i)` 可局部关掉大小写不敏感。
- `re:` 由用户显式提供，编译失败 → `Abort`（退出 1），错误信息里带原始 pattern。
- 不做取反、不做多 `--window` 逻辑与；一个 `--window` 足够，降低心智负担。

### 2.5 歧义处理（同名多窗口）

决策顺序（写死，测试覆盖）：

1. 0 个匹配 → 退出 **2**：`没有匹配 "..." 的窗口；用 --list-windows 查看候选。`
2. 1 个匹配 → 直接用。
3. 多个匹配且**当前激活窗口在匹配集合里** → 选它，stderr 打一行
   `匹配到 3 个窗口，使用当前激活的 [kitty] …`（倒计时仍会显示，用户可取消）。
4. 多个匹配、stdin 是 tty → 打印候选（**最上层在前**）并提示：
   ```
   匹配到 3 个窗口：
     1) 0x03a00007  kitty       12345  1  ~/src — nvim
     2) 0x03a00112  kitty       12345  2  ~/other
     3) 0x03a00201  Firefox     9999   1  GitHub
   选择 [1-3，回车=1，q=取消]:
   ```
   回车选 1，`q`/EOF → 退出 3（用户取消）。
5. 多个匹配、stdin 不是 tty（典型：`-f` 同时从管道读数据，或 CI）→ 退出 **2**，
   并把候选写到 stderr，提示改用 `id:` 或更精确的 `title:`。
   **不能**在这种情况下尝试用 stdin 提问——stdin 已经被 payload 占用。

> 为什么默认不"取最近激活"就完事：选错窗口 = 把内容敲进错误的应用，是本工具最严重的
> 事故形态。只有在"激活窗口本身就在候选里"时才敢自动选；其余情况必须让人确认或报错。

### 2.6 激活与焦点确认

```python
EWMH_ACTIVE = "_NET_ACTIVE_WINDOW"
SUBSTRUCT = 0x00080000 | 0x00100000   # SubstructureNotifyMask|SubstructureRedirectMask
ClientMessage = 33

def activate_window_x11(dpy, xid, *, timeout=0.6, interval=0.05,
                        expected: WindowInfo | None = None) -> bool:
    info = _window_info_raw(dpy, xid)          # 顺带验证窗口还活着
    if info is None:
        raise WindowGone(...)
    if expected and (info.cls, info.title) != (expected.cls, expected.title):
        raise WindowGone("窗口已被关闭并被复用（XID 复用），请重新 --list-windows")
    if _is_focused(dpy, xid):
        return True

    # 1) EWMH 请求 WM 激活（source=2 表示 pager/tool；l[1]=CurrentTime）
    if _atom(dpy, EWMH_ACTIVE, only_if_exists=True):
        ev = _client_message(xid, _atom(dpy, EWMH_ACTIVE), (2, 0, 0, 0, 0))
        with _x_trap(dpy):
            x11.XSendEvent(dpy, _root(dpy), False, SUBSTRUCT, ctypes.byref(ev))
            x11.XFlush(dpy)
        if _wait_focus(dpy, xid, timeout, interval):
            return True

    # 2) 兜底：raise + 直接设焦点（对没有 EWMH / 忽略请求的 WM）
    with _x_trap(dpy):
        x11.XRaiseWindow(dpy, xid)
        x11.XSetInputFocus(dpy, xid, 2, 0)     # RevertToParent, CurrentTime
        x11.XFlush(dpy)
    return _wait_focus(dpy, xid, min(0.3, timeout), interval)
```

焦点确认 `_is_focused(dpy, xid)`：

- `XGetInputFocus` 取 `focus`；`focus in (0, 1)`（None/PointerRoot）→ False。
- **相等 → True；否则从 `focus` 沿 `XQueryTree` 的 parent 向上走（最多 32 层），
  路上遇到 `xid` 就算成功**。原因：WM 重父化后焦点常在客户端子窗口（终端的
  文本区、浏览器的渲染子窗口），只比相等会 100% 误判。
- 上限 32 层防止 X 树异常导致死循环。

失败文案（退出 2，不降级、不改敲当前焦点）：

```
无法把焦点切换到 0x03a00007（[kitty] ~/src）：
窗口管理器可能启用了焦点抢占防护（i3/sway 的 focus_on_window_activation、
KWin 的"焦点窃取防护"、GNOME 的 activation 策略）。
可选：1) 去掉 --window，改用 -s 3 手动切换；
      2) 在该 WM 的设置里允许 activation；
      3) 用 --window id:<xid> 先确认窗口存在。
```

### 2.7 `--list-windows`

- 触发后只读、不激活、不注入，退出 0；Wayland（`caps["window_control"]` 为 False）
  → 退出 2 并说明。
- 可用 `--window` 过滤（同一套匹配逻辑），但**不触发歧义交互**，列出全部匹配。
- 输出：stdout 是 tty 时先打表头，否则纯数据；**6 列 TSV，title 最后一列**：

  ```
  ID          CLASS               PID     DESKTOP  ACTIVE  TITLE
  0x03a00007  kitty               12345   1        *       ~/src — nvim
  0x03a00112  firefox             9999    2        -       GitHub — Mozilla Firefox
  ```

- `ID` 用 `0x%08x`；`PID`/`DESKTOP` 缺失输出 `-`；`ACTIVE` 用 `*`/`-`
  （优先 `_NET_ACTIVE_WINDOW`，缺失时用 `focused_xid()` 向上找 client）。
- title 里的 `\t\r\n` 与 C0 控制字符替换成空格（防止破坏列/终端转义）；不做 48 字截断
  （机器可读优先，`describe_window()` 仍然截断）。
- 排序：叠放顺序从底到顶（最上层最后），与候选列表的"1) 最上层"相反——
  管道用户看 `tail -1` 即最上层；交互提示里再 reverse。

### 2.8 与倒计时/安全闸门联动

1. **定向成功后**，`countdown()` 显示 `[定向] [kitty] ~/src`，与"当前焦点"区分；
   实现上给 `countdown(seconds, typer, label=None)` 增加可选 label，
   `target_label()` 的结果作为默认值。
2. **倒计时结束、真正敲键前再复核一次焦点**：
   ```python
   if resolved and not typer.is_window_focused(resolved.xid):
       stderr "焦点已离开定向窗口，已取消（避免敲到别处）。"
       return 3
   ```
   这是 03 新增的关键安全点：`--window` 让用户敢把 `-s` 设成 0，但用户仍可能在
   倒计时中点了别处；复核失败**不抢回焦点**，直接放弃。
3. **多行 + 终端判定用"目标窗口"而不是"当前焦点"**（两者在激活成功后应一致，
   但用目标信息更确定）：`multiline_risk` 接收 `info` 或 `typer` + 目标 info。
   `--window class:kitty -f cmds.txt` 同样触发确认；`--yes` 才能跳过。
4. **`--dry-run` 绝不激活**（改焦点本身就是副作用）：
   ```
   目标窗口 : [定向] [kitty] ~/src (0x03a00007)
   激活     : 将发送 _NET_ACTIVE_WINDOW（dry-run 未执行）
   ```
5. **REPL**：`--window` 作为粘性目标，每次提交前重新解析+激活+倒计时；
   `:w <pattern>` 设置/查看，`:w -` 清除（约 25 行，可选但推荐）。REPL 里激活失败
   只打印 `已拦截: …`，不退出 REPL。
6. 不改变 `validate_payload`/root/文件类型等任何既有闸门。

## 3. B. `--paste-mode`（剪贴板直贴）

### 3.1 工具选择

```python
class Clipboard:
    name = "?"
    def targets(self) -> list[str] | None: ...   # 拿不到就 None
    def read(self) -> bytes: ...                 # 失败抛 ClipboardError
    def write(self, data: bytes) -> None: ...
```

| 会话 | 优先 → 次选 | 命令 |
|---|---|---|
| x11 | xclip → xsel | 读 `xclip -selection clipboard -o`；写 `xclip -selection clipboard -i`；targets `-o -t TARGETS` |
| wayland | wl-paste+wl-copy → xclip → xsel | 读 `wl-paste --no-newline`；写 `wl-copy`；targets `wl-paste --list-types` |
| 都没有 | None | 降级逐字符 + 一行安装提示 |

- 只用 `shutil.which` 探测；`subprocess.run(argv, ...)` **argv 数组直传、绝不 shell**，
  与 02 的 SECURITY 表述一致。
- `xclip -i` / `wl-copy` 会 fork 子进程持有 selection，`run` 返回即代表"已接管"；
  后续再写入会替换前一个持有者，不需要手动 kill。
- 读超时 1s、写超时 2s；超时 → `ClipboardError`。
- 不引入第三方库；`wl-copy` 属于可选增强，没有也能走 xclip。

### 3.2 备份 / 恢复策略（安全核心）

```python
CLIP_READ_TIMEOUT = 1.0
CLIP_WRITE_TIMEOUT = 2.0
CLIP_SETTLE = 0.08          # 等 selection owner 生效
MAX_CLIP_BACKUP = 4 << 20   # 4 MiB，超过则认为"无法安全备份"
PASTE_WAIT_DEFAULT = None   # None = 按体积自动
```

流程：

```
targets = clip.targets()
if targets is not None and 没有 {UTF8_STRING, STRING, TEXT, text/plain*}:
    -> ClipboardUnsafe（非文本，无法备份）
if targets is None:  # xsel 不支持列 targets
    try read()；失败 -> ClipboardUnsafe
backup = clip.read()        # b"" 是合法备份（空剪贴板）
if len(backup) > MAX_CLIP_BACKUP: -> ClipboardUnsafe
try:
    clip.write(text.encode("utf-8"))
    time.sleep(CLIP_SETTLE)
    typer.press(paste_key)          # ctrl+v / ctrl+shift+v
    time.sleep(paste_wait)
finally:
    if backup is not None and not args.no_restore_clipboard:
        try: clip.write(backup)
        except Exception: stderr("⚠ 剪贴板恢复失败，原内容已丢失")
```

- **备份失败/非文本/超 4 MiB → 默认退出 2**，文案：
  ```
  剪贴板当前内容无法安全备份（非文本 / 超过 4 MiB / 读取超时）。
  为避免覆盖你的剪贴板，已停止。确认可以覆盖时加 --no-restore-clipboard。
  ```
  这是把"数据丢失"当安全问题对待；比"先覆盖再说"更符合本项目的安全默认值。
- 备份成功但恢复失败：只警告，不影响已完成的输入（不要因此返回非零把成功当失败）。
- 空剪贴板（`b""`）也要恢复：`printf '' | xclip` 可把 selection 置空；
  若工具拒绝空输入，警告即可。
- **恢复时机**：目标应用是在收到 Ctrl+V 之后异步向 selection owner 取数据的；
  恢复太早会把旧内容贴进去。默认等待按体积：
  `wait = 0.5 if len(data) <= 200_000 else min(3.0, 0.5 + len(data)/1_000_000)`；
  `--paste-wait 秒` 显式覆盖（0–10）。文档写明：远程桌面/慢应用可调大。
- xclip 的 `-loops 1` **不要用**：它只服务一次转换就退出，若目标没取走就变成空剪贴板；
  默认让 xclip 持续持有，恢复时自然替换。

### 3.3 Ctrl+V vs Ctrl+Shift+V

- 终端里 `Ctrl+V` 在 readline/zsh 里是 quoted-insert（"下一个字符原样插入"），
  **不是粘贴**；多数终端粘贴是 `Ctrl+Shift+V`（kitty/alacritty/gnome-terminal/
  konsole/xfce4-terminal/tilix/wezterm），xterm/uxterm/urxvt/rxvt 常用 `Shift+Insert`。
- 自动规则：
  ```python
  PASTE_SHIFT_INSERT = {"xterm", "uxterm", "urxvt", "rxvt", "st", "st-256color", "termite"}
  if is_terminal(info):
      key = "shift+insert" if (info["class"] or "").lower() in PASTE_SHIFT_INSERT else "ctrl+shift+v"
  else:
      key = "ctrl+v"
  ```
- `--paste-key <combo>`（如 `ctrl+shift+v` / `shift+insert` / `ctrl+v`）显式覆盖；
  校验 `is_combo` + 修饰键合法，非法 → 退出 1。`--paste-key` 只能在 `--paste-mode`
  下使用；单独给出 → 退出 1（避免误以为改了 `-k`）。
- 终端类名判定复用现有 `TERMINAL_CLASSES`/`is_terminal()`。
- 失败无感知：某些应用不响应 Ctrl+V（自定义快捷键/游戏），本工具无法检测"是否贴上"；
  README/`--help` 明确说明，建议先用 `--dry-run` 确认目标。

### 3.4 哪些场景不用 paste-mode

| 场景 | 处理 |
|---|---|
| `--dry-run` | **绝不**读/写剪贴板，只打印"将写入剪贴板并发送 X" |
| `-k` 组合键混用 | 拒绝：`--paste-mode 不能与 -k 混用`（退出 1）。paste-mode 只处理单个文本 payload |
| 目标不明确/非文本应用 | 仍可用，但用户自负；文档说明"看不到是否贴上" |
| 密码/敏感内容 | 文档明确警告：剪贴板是全局的，剪贴板管理器（klipper/clipman）可能留存历史；恢复≠擦除 |
| 剪贴板含大图/非文本 | 默认拒绝（见 §3.2），除非 `--no-restore-clipboard` |
| 用户显式要逐字符 | 不加 `--paste-mode` 即可；`--paste-mode` 永远 opt-in |
| REPL 提交 | 与 CLI 相同：`--paste-mode` 在 REPL 启动时生效，每次提交走 `send_text()`，仍先倒计时/确认；`:t` 显示 paste 状态 |
| 后端 `combos=False` | 退出 2（理论上 02 的三个后端都支持组合键） |
| Wayland 但只有 xclip | 允许（XWayland 桥接通常可用），但打印一行提示；失败则降级逐字符 |

### 3.5 失败降级

- 找不到任何工具：stderr 一行
  `未找到 xclip/xsel/wl-copy，--paste-mode 降级为逐字符输入。安装：sudo apt install xclip`，
  然后正常逐字符输入。**不报错退出**——用户要的内容仍应被输入，只是慢。
- 写入/读取中途 `ClipboardError`：**在还没按 Ctrl+V 之前**失败 → 降级逐字符（并警告）；
  已经按了 Ctrl+V 之后失败 → 不重复输入（避免双份），恢复尽力，退出 0 并警告。
- 大文本 + 降级：打印预计耗时 `len*delay` 秒，给用户 Ctrl-C 的机会（REPL 可用）。

## 4. C. 提速

### 4.1 现状与瓶颈

每个字符：`XTestFakeKeyEvent(press)` + `XTestFakeKeyEvent(release)` + `XFlush` +
`time.sleep(delay)`。`delay=0.008` 时理论 125 字/秒；实际约 115–122（flush/syscall 开销）。
`delay=0` 时每字符仍有 2 次 ctypes 调用 + 1 次 `XFlush`，约 3k–8k 字/秒。

### 4.2 方案：批量事件 + 单次 flush + XTest 服务端 delay

```python
QUEUE_BUDGET_MS = 250       # 服务端最多排队 250ms 的按键
FLUSH_EVERY_NODELAY = 256   # delay==0 时每 256 字符 flush 一次

def _tap_raw(self, kc, shift=False, delay_ms=0):
    d = self.dpy
    if shift and self.shift_kc:
        xtst.XTestFakeKeyEvent(d, self.shift_kc, True, 0)
    xtst.XTestFakeKeyEvent(d, kc, True, delay_ms)   # 只有 press 带 delay
    xtst.XTestFakeKeyEvent(d, kc, False, 0)
    if shift and self.shift_kc:
        xtst.XTestFakeKeyEvent(d, self.shift_kc, False, 0)

def type_text(self, text):
    delay_ms = int(self.delay * 1000 + 0.5) if self.delay > 0 else 0
    budget = max(1, QUEUE_BUDGET_MS // delay_ms) if delay_ms else FLUSH_EVERY_NODELAY
    n = 0
    try:
        for ch in text:
            if ch == "\n":   self._press_raw("enter", delay_ms); n += 1
            elif ch == "\t": self._press_raw("tab", delay_ms);   n += 1
            elif ch == "\r": continue
            else:
                kc, shift = self.keycode_for(_char_keysym(ch))
                if kc:
                    self._tap_raw(kc, shift, delay_ms); n += 1
                else:
                    x11.XFlush(self.dpy); n = 0      # 先清空队列，再走慢路径
                    self.type_char(ch)               # 保持 remap/restore 的原有顺序
                    continue
            if n >= budget:
                x11.XFlush(self.dpy); n = 0
    finally:
        x11.XFlush(self.dpy)      # 异常/中断也把已排队事件送出去
```

关键约束：

1. **Unicode 字符绝不批量**：`_remap()` 需要 `XSync` 往返，且 `type_char()` 的
   `try/finally: _restore_keymap()` 依赖"事件处理完再还原"。批量路径遇到不可映射字符
   时先 `XFlush` 清空队列，再原样调用 `self.type_char(ch)`（保留旧时序，包括现有
   `_unicode` 内的 sleep），保证键盘映射一定还原。
2. **`--delay` 语义不变**：仍是"相邻字符之间的间隔"。批量路径把它换算成整数毫秒，
   放在每个字符 `press` 事件上；release 不带 delay。`delay=0` → 0，纯批量。
   精度从浮点秒变成 1ms（`0.0004 → 0`），文档写明。
3. **`type_char()`/`press()` 保持原实现不变**（单字符/组合键仍立即 flush + sleep），
   只有 `type_text()` 走新路径。这样 `-k ctrl+v`、REPL 的 `type_char` 语义零变化。
4. **分块上限**：服务端排队 ≤250ms。`delay=8ms` 时每 31 字 flush 一次；
   `Ctrl-C`/SIGTERM 最多还会再送出约 250ms 的按键（无法撤回已排队事件）。
   `delay=0` 时每 256 字 flush 一次。
5. **异常安全**：`finally` 里 flush；shift 的释放事件与 press 同批排队，
   不会出现"按住 Shift 不松"。
6. **必须实测 XTest delay 是否阻塞服务器**：若某些 Xorg/驱动上 `delay` 是
   "服务器睡眠"而不是"延迟调度"，会造成整机输入卡顿。验证方法见 §4.4；
   若确认会阻塞，则退回"批量 flush + 客户端每字符 `time.sleep(delay)`"的保守版
   （用一个模块常量 `USE_XTEST_DELAY = True/False` 切换，测试同时覆盖两种）。

### 4.3 预期吞吐（诚实的数字）

| 场景 | 现状 | 03.3 之后 |
|---|---|---|
| `-d 0.008`（默认） | ~115–122 字/秒 | ~122–124 字/秒（+1–5%，瓶颈是 8ms 本身） |
| `-d 0`（本地 X11） | ~3k–8k 字/秒 | ~15k–60k 字/秒（受 XTest/服务器上限，5–20×） |
| 1 MiB 文本，`-d 0.008` | ≈2.3 小时 | 仍 ≈2.3 小时 → **应改用 `--paste-mode`（≈0.5–1s）** |

结论：03.3 主要价值是"零延时/低延时场景"和降低 CPU/syscall；**大文本请引导用户用
paste-mode**，README 必须写清楚，避免用户以为批量注入把 1 MiB 变成了秒级。

### 4.4 测量方法

**不做 `--bench` 子命令**：任何"发 N 个按键"的基准都会打到当前焦点窗口，有误输入风险，
收益不值得。用 README 手测步骤：

```bash
# 1) 在一个临时终端里接收（不会执行内容）
xterm -e 'cat > /tmp/ap.out' &
sleep 0.5
# 2) 生成 20000 字符样本
python3 - <<'EOF'
open('/tmp/sample.txt','w').write(('abcdefghij' * 2000))
EOF
# 3) 目标切到 xterm 后计时（-s 给 2 秒切窗口）
/usr/bin/time -f '%e 秒' python3 autopaste.py -s 2 -d 0.008 -f /tmp/sample.txt
# 4) 校验没有丢字/串字
cmp /tmp/sample.txt /tmp/ap.out && echo IDENTICAL
```

- 吞吐 = `wc -m /tmp/sample.txt` / 秒数。
- 丢字检测就是 `cmp`；首个差异位置即丢字点。
- 服务端 delay 是否卡顿：注入期间在另一个窗口拖动鼠标/看时钟，若鼠标明显顿挫，
  说明该 X 服务器上 delay 阻塞，切回保守版。
- 远程桌面（VNC/RDP）需要单独测：把 `-d` 提到 0.02–0.05 再测，记录丢字率。

### 4.5 风险与对策

- **太快丢字**：不做"自动重试"——无法知道丢了哪个字符，重试会重复输入。对策：
  `--delay` 下限不强制但文档建议 ≥0.005；`--delay 0` 且文本 >2000 字符时 stderr 打一行
  `零延时批量发送；若目标应用丢字请加 -d 0.005`（不阻塞）。
- **中断后仍有 250ms 按键**：分块上限 + 文档说明；粘贴模式是更好的大文本路径。
- **服务端 delay 阻塞**：`USE_XTEST_DELAY` 开关 + 实机验证，见上。
- **IE/浏览器/Electron 对注入敏感**：不特殊处理，靠 delay。

```python
    """读 32 位属性；缺失/类型不符返回 None。"""
    ...


def _prop_text(dpy, win: int, prop: int, req_type: int) -> str | None:
    """读 8 位属性；UTF-8 解码失败返回 None（由调用方决定回退）。"""

def _window_info_raw(dpy, xid: int) -> WindowInfo | None:
    attrs = _attrs(dpy, xid)
    if attrs is None:
        return None
    title = _prop_text(dpy, xid, _atom(dpy, "_NET_WM_NAME", True),
                       _atom(dpy, "UTF8_STRING", True))
    if title is None:
        title = _fetch_name(dpy, xid)          # 现有 XFetchName + _decode
    cls, instance = _class_hint(dpy, xid)      # 现有 XGetClassHint
    pid = (_prop32(dpy, xid, _atom(dpy, "_NET_WM_PID", True), XA_CARDINAL) or [None])[0]
    desk = (_prop32(dpy, xid, _atom(dpy, "_NET_WM_DESKTOP", True), XA_CARDINAL) or [None])[0]
    if desk == 0xFFFFFFFF:
        desk = None
    return WindowInfo(xid, cls or "", instance or "", title or "", pid, desk)


def list_windows_x11(dpy) -> list[WindowInfo]:
    root = _root(dpy)
    clients = _prop32(dpy, root, _atom(dpy, "_NET_CLIENT_LIST", True), XA_WINDOW)
    stacking = _prop32(dpy, root, _atom(dpy, "_NET_CLIENT_LIST_STACKING", True), XA_WINDOW) or []
    if not clients:
        clients = _walk_clients(dpy, root)     # XQueryTree 递归 + viewable 过滤
    order = {x: i for i, x in enumerate(stacking)}
    out = []
    for xid in clients:
        if _skip_window_type(dpy, xid):
            continue
        info = _window_info_raw(dpy, xid)
        if info and (info.cls or info.instance or info.title):
            out.append(info)
    out.sort(key=lambda w: order.get(w.xid, -1))
    return out


def _walk_clients(dpy, win, depth=0) -> list[int]:
    if depth > 16:
        return []
    out = []
    for child in _children(dpy, win):
        a = _attrs(dpy, child)
        if a is None:
            continue
        if a.override_redirect:
            continue
        if a.map_state == 2:                   # IsViewable
            info = _window_info_raw(dpy, child)
            if info and (info.cls or info.title):
                out.append(child)
        out += _walk_clients(dpy, child, depth + 1)
    return out
```

> `_children()` 必须实现为：`XQueryTree` 取 `children` 指针，`ctypes.string_at`/
> 切片转成 Python list 后**立刻 `XFree(children)`**，再递归；否则每枚举一次泄漏
> 一份子窗口数组。递归深度上限 16 层防止异常 X 树。

```python
def match_windows(wins, pattern: str) -> list[WindowInfo]:
    kind, text = parse_pattern(pattern)
    if kind == "id":
        try: xid = int(text, 0)
        except ValueError: raise Abort(f"--window id: 需要整数: {text!r}")
        return [w for w in wins if w.xid == xid]
    if kind == "pid":
        try: pid = int(text, 0)
        except ValueError: raise Abort(f"--window pid: 需要整数: {text!r}")
        return [w for w in wins if w.pid == pid]
    if kind == "re":
        try: rx = re.compile(text, re.IGNORECASE)
        except re.error as e: raise Abort(f"--window 正则无效: {e}")

    needle = text.casefold()
    def hit(w):
        fields = {"any": (w.cls, w.instance, w.title),
                  "class": (w.cls, w.instance),
                  "title": (w.title,)}[kind]
        return any(needle in (f or "").casefold() for f in fields)
    return [w for w in wins if hit(w)]
```

### 6.3 激活（含 X 错误陷阱）

```python
_ERR_FUNC = ctypes.CFUNCTYPE(ctypes.c_int, ctypes.c_void_p, ctypes.c_void_p)

@_ERR_FUNC
def _ignore_x_error(dpy, ev):
    return 0

@contextlib.contextmanager
def _x_trap(dpy):
    old = x11.XSetErrorHandler(_ignore_x_error)
    try:
        yield
    finally:
        x11.XSync(dpy, False)
        x11.XSetErrorHandler(old)
```

> `XSetErrorHandler` 必须保留 Python 回调的全局引用（`_ignore_x_error` 已由装饰器

### 6.4 paste

```python
def paste_text(typer, text: str, *, clip, paste_key: str,

    backup = None

            raise ClipboardUnsafe(...)
        backup = clip.read()
        if len(backup) > MAX_CLIP_BACKUP:

                clip.write(backup)
            except Exception as e:
                sys.stderr.write(f"⚠ 剪贴板恢复失败：{e}\n")
```

### 6.5 批量 type_text

见 §4.2。补充 `_press_raw(name, delay_ms)`：复用 `press()` 的解析逻辑，抽出
`_resolve_key(name) -> (kc, shift, mods)`（纯函数，便于测试），`press()` 与
`_press_raw()` 共用。

| 1 | **Xlib 默认错误处理器 `exit(1)`** | 窗口在枚举/激活之间关闭（BadWindow）、对未映射窗口 XSetInputFocus（BadMatch） | 进程直接退出，错误信息不可控 | `_x_trap` + `XSetErrorHandler` 吞错 + `XSync`；测试 27；所有窗口操作都包起来 |
