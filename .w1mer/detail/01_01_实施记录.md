   - classifiers 覆盖 Python 3.8–3.13、`Operating System :: POSIX :: Linux`、
     `Environment :: X11 Applications` 等。
2. **tests/**（标准库 unittest，零第三方）
   - `support.py`：`FakeX11` / `FakeXtst` 假后端、`redirect_std`、`editor_input`；
     测试通过 `mock.patch.object(autopaste, "x11"/"xtst", fake)` 注入，
     **生产代码零改动**（未提前做任务 02 的后端抽象）。
   - `test_core.py`：`validate_payload`（控制字符/`--allow-control`/1 MiB 上限/`\n\t`

   - `test_typer.py`：`\n`→Return、`\t`→Tab、普通字符→keycode、Unicode→

## 说明 / 注意

- setuptools ≥ 77 对 `project.license` 的 TOML table 形式给出弃用告警
  （2027-02 前移除）。保留 table 是因为 `requires-python >= 3.8` 时
  旧 setuptools（<77）不认识 `license` SPDX 字符串与 `project.license-files`，
  会让 3.8 安装失败；等放弃 3.8 后可改为 `license = "MIT"` +
  `license-files = ["LICENSE"]`。
- 测试导入 `autopaste` 时会 dlopen `libX11`/`libXtst`，因此 CI 需要这两个
  运行库（ubuntu-latest 自带；既有 check job 早已依赖这一点）。
- 未做任务 02 的后端抽象：`Typer` 仍直接使用 X11，测试仅靠替换模块级
  `x11`/`xtst` 全局完成隔离。
