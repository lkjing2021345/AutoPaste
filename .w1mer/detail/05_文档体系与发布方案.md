## 0. 结论摘要（先看这 10 条）

1. **版本 = `1.1.0`**。`1.0.0 → 1.1.0` 之间没有任何已发布版本，所以把 02（Wayland 后端）与
   03（窗口定向/剪贴板直贴/批量提速）两批 feature 合并进同一个 MINOR 是合法的；**不需要**
   因为「03 已落地」而改成 1.2.0（旧方案 §4.1 的那条分支只有在 v1.1.0 已经发布过时才成立）。
2. **发布前必须先确认 `git tag --list 'v1*'` 的输出**：若 `v1.1.0` 已存在 → 停，改 1.1.1/1.2.0；
   若 `v1.0.0` 不存在 → CHANGELOG 的 compare 链接会 404，先补 tag 或改用 compare/<首个 commit>。
3. **1.1.0 严格不含任务 04**：REPL 历史/持久化、`:p`、`:w <file>` 保存、`:win` 改名、
   `--verbose`/`--quiet`、`config.toml`、退出码统一、REPL 倒计时后焦点复核、countdown EOF 修复，
   一律**不得**出现在 README/docs/cli.md/CHANGELOG/Release notes。切分表见 §5.1。
4. HEAD 的 CLI 是 **22 个 action**（21 个 optional + 1 个 positional），不是旧方案的 15 个；
   新增的 8 个是 `--safe`、`--window`、`--list-windows`、`--json`、`--paste-mode`、`--paste-key`、
   `--paste-wait`、`--no-clipboard-backup`（别名 `--no-restore-clipboard`）。完整表见 §1.1。
5. `capabilities()` 现在是 **10 个键**（含 `window_control`、`escapes_supported`、
   占位 `can_paste_mode`），旧方案的 6 列矩阵已过期。矩阵见 §1.4。
6. **`--help` 与 `docs/cli.md` 的唯一校验入口是 `python3 tools/gen_cli_docs.py --check`**，
   不要用 `diff` 人工比对（argparse 会按宽度换行）。生成器同时生成 flags 表与能力矩阵两个区块。
7. **`argparse` 自身的用法错误退出码是 2**（未知选项/非法 choice/非数字），而 `--delay 99`
   这类数值越界是 1。现有 README 的退出码表把「参数错误」笼统写成 1，**这是当前文档的错误**，
   `docs/cli.md` 必须写清两条路径（§1.3）。
8. **测试命令必须加 `< /dev/null`**：`test_ambiguous_non_tty_exits_2` 依赖真实
   `sys.stdin.isatty()`，在交互式终端里跑会挂住（R_03 T1）。这不是 05 要修的代码，但发布
   checklist 必须绕开。
9. **sdist 目前会把 `docs/` 漏掉**（没有 `MANIFEST.in`，setuptools 不会自动收 markdown 目录）。
   05 必须新增 `MANIFEST.in`，否则 GitHub Release 的 `.tar.gz` 里没有文档。
10. **REPL 的窗口命令仍是 `:w <pattern>`**（`repl()` 在 `autopaste.py:2239`，BANNER/HELP 同样），
    不是 04 计划里定的 `:win`。1.1.0 的文档按**实际代码**写 `:w`；`:win` 是 1.2.0 的 breaking
    change，留给 04 的 CHANGELOG。

### 1.2 `--help` 结构（implementer 第 1 步实跑核对）

```

                 [--paste-key COMBO] [--paste-wait 秒]
                 [--no-clipboard-backup] [--allow-root] [-V] [text ...]

把文本敲进当前聚焦的窗口（X11 用 XTEST，Wayland 用 wtype/ydotool，零第三方依赖）。
不带参数运行进入交互 REPL。

  -h, --help            show this help message and exit
  ...（22 个 action 各一行）

  autopaste ...（10 条，含 --list-windows / --window / --paste-mode）
```

### 1.4 `--list-backends` 输出（`format_backends()`，`autopaste.py:2521-2581`）

固定表头（注意 `后端` 后是 6 个空格、可用后 4 个空格）：

```
后端      可用  探测依据
x11        是    DISPLAY=:0，libX11/libXtst 可加载
wtype      否    未在 PATH 找到
ydotool    否    已安装但找不到 socket（ydotoold 未运行？）

```

- 表头与行格式是**契约**（`tests/test_backends.py::test_list_backends_output` 断言子串），
  `docs/backends.md` 可以用示意输出，但要注明「探测依据随环境变化」。
- 最后两行恒为 `当前会话: x11|wayland|unknown` 与 `auto 将选择: <name>|（无可用后端）`。
- ydotool 行在支持 `-e` 时会追加 `，支持 -e（关闭转义）`，旧版追加
  `，不支持 -e（旧版 < 1.0.4…）`——**文档不要写死这一段**。

### 1.5 `--list-windows` 输出（`main()` 的 `args.list_windows` 分支）

- TSV，6 列：`ID CLASS PID DESKTOP ACTIVE TITLE`（`WINDOW_HEADER`，`\t` 分隔）。
- **表头只在 `sys.stdout.isatty()` 为真时打印**；重定向/管道下没有表头，只有数据行。
- 行格式：`0x03e00005\tfirefox\t1234\t0\t*\t文档 — Mozilla Firefox`
  （`ACTIVE` 为 `*` 或 `-`；`PID`/`DESKTOP` 未知为 `-`；标题里的控制字符替换为空格）。
- `--json` 输出对象数组，每项含 `xid`（int）、`cls`、`instance`、`title`、`pid`、`desktop`、
  `id`（`0x%08x` 字符串）、`active`（bool）。
- Wayland 后端（`window_control=False`）退出 **2**，错误信息提示 `--backend x11`。

### 1.6 能力矩阵（`capabilities()` 实际返回值，10 键）

| 后端 | can_focus_info | unicode | needs_remap | combos | per_char_delay | daemon | window_control | escapes_supported | can_paste_mode |
|---|---|---|---|---|---|---|---|---|---|
| x11 | ✔ | ✔ | ✔ | ✔ | ✔ | ✘ | ✔ | ✔ | ✘ |
| wtype | ✘ | ✔ | ✘ | ✔ | ✔ | ✘ | ✘ | ✔ | ✘ |
| ydotool | ✘ | ✘（仅 ASCII） | ✘ | ✔ | ✔ | ✔（需 ydotoold） | ✘ | 运行期探测（`-e`，≥1.0.4） | ✘ |

- `can_paste_mode` 三个后端**都是 False**，是内部占位键；`docs/backends.md` 的 AUTO 矩阵
  **不要**把它当用户能力列出来（列 8 列：看焦点 / Unicode / 重映射 / 组合键 / 每字符延时 /
  守护进程 / 窗口定向 / 转义支持）。
- ydotool 的 `escapes_supported` 是**实例**属性（`__init__` 里探测一次），生成器不能直接
  `cls.capabilities(SimpleNamespace(name=...))`，见 §4.2。

### 1.7 auto 选择规则（`detect_session()` 1568 / `choose_backend()` 1601）

1. `XDG_SESSION_TYPE` 优先：`wayland`/`x11`（XWayland 下 `DISPLAY` 存在也不算 X11）。
2. 否则 `WAYLAND_DISPLAY` → wayland，`DISPLAY` → x11，否则 unknown。
3. 真 X11 → `x11`（永不跨会话回退）。
4. Wayland：`XDG_CURRENT_DESKTOP` 含 `GNOME` → `ydotool` → `wtype`；其他 → `wtype` → `ydotool`。
   ydotool 还必须找到 socket（`YDOTOOL_SOCKET` / `$XDG_RUNTIME_DIR/.ydotool_socket` / `/tmp/.ydotool_socket`）。
5. 都不可用 → `BackendUnavailable`（退出 2）+ 发行版安装命令。
6. 显式 `--backend` 原样返回，不做静默跨会话回退。

## 2. 文档结构（沿用旧方案，边界不变）

### 2.1 目标文件树

```
README.md              # 入口，≤ 90 行
README.en.md           # 英文摘要，≤ 45 行，全部链接中文 docs
SECURITY.md            # 留在根目录（威胁模型唯一权威）

├── cli.md             # 参数唯一权威（AUTO:flags）+ 键名 + 退出码 + 示例
```

### 2.3 必须写进 `docs/README.md` 的三条硬规则

1. **一个事实只有一个 owner**：先查上表，不属于自己就改成链接 + 一句上下文。
2. **AUTO 区块禁止手改**：`docs/cli.md` 的 `<!-- BEGIN AUTO:flags -->` /
   `<!-- END AUTO:flags -->`、`docs/backends.md` 的 `<!-- BEGIN AUTO:matrix -->` /
   `<!-- END AUTO:matrix -->` 只由 `tools/gen_cli_docs.py` 生成。
3. **不写未实现的 flag**：`tests/test_docs.py` 扫描所有文档里的 `--xxx`，不在
   `build_parser()` 里的直接失败。**这条专门拦住 1.1.0 里不该出现的
   `--verbose`/`--quiet`/`--no-inject`（04/未来任务）。**

### 2.4 路径与锚点（同旧方案）

- README→docs：`docs/usage.md`；docs→根：`../SECURITY.md`；docs 内部：`cli.md`。
- 禁止 `raw.githubusercontent.com` 绝对链接。
- 跨文件锚点只给四个热点加显式 ASCII id：`#flags`、`#exit-codes`、`#backends-matrix`、`#key-names`。
- 每个 docs 文件顶部一行面包屑：`[← README](../README.md) · [文档索引](README.md)`。
- 本期不加徽章。

### 4.1 `tools/gen_cli_docs.py`（新增，~110 行，纯标准库）

职责：

1. `sys.path.insert(0, repo_root)` 后 `import autopaste`。**安全**：libX11 是惰性加载
   （`x11 = None`，`_load_x11()` 才 dlopen），`test_help_works_without_libx11` 已证明导入不碰 X。
2. 生成 `docs/cli.md` 的 flags 区块：

```python
def flag_rows(parser):
    for a in parser._get_positional_actions() + parser._get_optional_actions():
        if isinstance(a, argparse._HelpAction):
            continue
        names = ", ".join(f"`{s}`" for s in (a.option_strings or [a.dest]))
        # 取值列：choices / metavar / type / default；nargs==0 或 action 为
        # store_true/store_false/version 时写 "—"；action=="append" 写 "可重复"
        yield f"| {names} | {value_col} | {help_text} |"
```

   - `--version` 的 `help` 是 `None` → 兜底 `打印版本号后退出`。
   - `-h/--help` 跳过（argparse 的英文 help 不进文档）。
   - `--no-clipboard-backup` 的 `option_strings` 有两个，必须都列（别名不能漏）。
3. 生成 `docs/backends.md` 的矩阵区块：

```python
import types
def caps(cls, name):
    obj = types.SimpleNamespace(name=name, escapes_supported=None)
    return cls.capabilities(obj)      # 方法体只读 self.name / self.escapes_supported
```

   **这是对旧方案的必须修正**：`YdotoolBackend.capabilities()` 读 `self.escapes_supported`
   （`autopaste.py:1558`），旧方案的 `SimpleNamespace(name=name)` 会 `AttributeError`。
   生成时 `escapes_supported is None` 渲染成 `按版本探测（≥1.0.4）`，不要渲染成 `✘`。
   列只取 8 个用户能力键，`can_paste_mode` 不渲染（全 False 的内部占位）。
4. 区块替换只认 `<!-- BEGIN AUTO:<name> -->` … `<!-- END AUTO:<name> -->`，找不到标记 → 退出 1
   并提示「docs/cli.md 缺少 AUTO:flags 标记」。
5. `--check` 模式：只生成 + `difflib.unified_diff` 摘要到 stderr，任何差异 `sys.exit(1)`；
   默认模式写回文件（UTF-8，保留文件其余内容）。
6. **自校验**：用公开的 `parser.format_help()` 交叉验证——每个 action 至少有一个
   `option_strings` 出现在 help 文本里（`-h/--help` 除外）；别名 `--no-restore-clipboard`
   不出现属正常，所以按「至少一个」而不是「全部」。失败时提示「argparse 私有 API 变了，
   请改用 format_help 解析」。
7. 生成顺序固定：先写 flags、后写 matrix；`--check` 对两个区块都校验。

**不要**从 `format_help()` 反解析生成表（`RawDescriptionHelpFormatter` 会按宽度换行）。

```markdown
- pip/pipx 入口现在也注册 `SIGINT/SIGTERM/SIGHUP` 并返回 130，`atexit` 的键位还原
  不再被 SIGTERM 绕过。
- `--window`：激活后轮询 `XGetInputFocus`，倒计时结束再复核一次，焦点离开立即取消（退出 3）；
  多候选不猜，非交互环境退出 2。
- `--paste-mode`：备份失败/非文本/超 4 MiB 一律退出 2（fail-closed），恢复放在 `finally`。
- 批量注入中断后最多再送出约 250ms 已排队按键；对时序敏感时用 `--safe`。
```

**不要**写进 1.1.0：REPL 焦点复核、REPL 多行确认、历史/配置文件、`:win`、`--verbose`。

### 5.3 tag 策略

- 格式 `v1.1.0`（带 `v`），与 compare 链接、`pipx install git+...@v1.1.0` 一致。
- **annotated 必须**：`git tag -a v1.1.0 -m "AutoPaste 1.1.0" <SHA>`；有 GPG 用 `-s`，
  没有就 `-a`（签名非强制，不阻塞发布）。
- 只打在**最后一个 commit**（05.3）上；打之前该 commit 的 CI 三 job 全绿
  （`package` job 会 `pip install .` + `autopaste --version`，等于验证打包路径）。
- **不 push**（CONVENTIONS）：implementer 只 commit + 本地 tag；推送由编排者执行。
