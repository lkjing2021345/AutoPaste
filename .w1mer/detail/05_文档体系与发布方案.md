## 0. 结论摘要（先看这 8 条）

1. `docs/` 拆 **5 个文件**：`README.md`（索引）、`usage.md`（场景教程）、`cli.md`（**唯一**参数权威，flag 表自动生成）、`backends.md`（能力矩阵 + auto 规则 + 安装/权限）、`design.md`（架构 + 与 xdotool 的区别）；`troubleshooting.md` 合并进 `usage.md` 尾部的症状表，不单独建文件（省一个"没内容可写"的薄文件）。
2. **`SECURITY.md` 留在仓库根，不搬进 `docs/`**。它是 GitHub Security 标签页识别的规范位置，且 `autopaste.py` 的模块 docstring、`--help` epilog、pyproject 的 sdist 都按裸文件名引用它。ROADMAP 里的 "security" 由"更新根目录 SECURITY.md + 在 `docs/README.md` 索引里指向它"满足——**不建 `docs/security.md`**，避免威胁模型出现两个版本。
3. `README.en.md` **只保留摘要（≤45 行）并全部链接中文 docs**，不建 `docs/en/`。双写必然漂移，而我们只有一个人维护。
4. 防漂移的最小可执行实现是 **一个生成器 + 一个测试文件**：`tools/gen_cli_docs.py` 从 `build_parser()` 生成 `docs/cli.md` 的 `<!-- BEGIN AUTO:flags -->` 区块；`tests/test_docs.py` 在现有 `tests` job 里做 5 条断言（flag 表同步 / 文档提到的 flag 真实存在 / 链接可达 / 能力矩阵==`capabilities()` / 退出码已文档化）。**不改 `autopaste.py` 的运行时代码**（除 `__version__` 与 epilog 收尾）。
5. 眼下已有 7 处**具体**漂移（§2.3 列表），05.1 必须逐条修掉，而不是只搬文件。
6. 版本：`1.0.0 → 1.1.0`（新增后端/flags = 向后兼容的新功能 → MINOR）。tag 用 **annotated**（有 GPG key 则 `-s`），格式 `v1.1.0`，**只打在最后那个 commit 上**，由编排者推送（CONVENTIONS 明确 implementer 不 push）。
7. PyPI 名 `autopaste` **大概率被占**；05 的发布目标是 **GitHub tag + Release（附 wheel/sdist）**，PyPI 作为后续可选项，先跑 §5.2 的核对步骤再决定。README 首屏必须 3 行内讲清"和 xdotool 的区别"与安全警告。
8. 拆 3 个 commit（05.1 文档 / 05.2 防漂移工具 / 05.3 版本与发布），**顺序不可换**：生成器要求 `docs/cli.md` 先存在；tag 必须指向最后一个 commit。

### 1.2 代码侧的唯一事实（05 文档必须照抄这些）

`build_parser()`（约 1273 行起）当前参数全集，共 **15 个 action**：

| 参数 | 类型/默认 | 备注 |
|---|---|---|
| `text`（positional, `nargs="*"`） | 列表 | `-` 表示 stdin |
| `-d, --delay` | float, `0.008` | 上限 5（`MAX_DELAY`） |
| `-s, --sleep` | float, `None` | 上限 3600（`MAX_COUNTDOWN`）；REPL 默认 2.0 |
| `-f, --file` | str | 仅普通文件，≤ 1 MiB |
| `-k, --key` | append, `[]` | 可重复 |
| `-n, --no-newline` | flag | 只影响 file/stdin |
| `--repl` | flag | 强制进 REPL |
| `--dry-run` | flag | 退出 0，不发按键 |
| `-y, --yes` | flag | 跳过确认 |
| `--allow-control` | flag | 默认拒绝 C0 控制字符 |
| `--backend` | choices `auto\|x11\|wtype\|ydotool`, `auto` | |
| `--list-backends` | flag | 打印诊断后退出 0 |
| `--allow-root` | flag | 默认拒绝 root |
| `-V, --version` | action=version | `autopaste <__version__>` |

`main()` 的返回码：`0` 成功 / `1` 参数值或内容校验失败（`Abort`、`BackendError`、无输入时打印 help）/ `2` 环境或安全拒绝（root、`BackendUnavailable`）/ `3` 用户取消确认 / `130` Ctrl-C 或 countdown 中断。

后端能力矩阵（`capabilities()` 的返回值，05 文档要 1:1 复述）：

| backend | can_focus_info | unicode | needs_remap | combos | per_char_delay | daemon |
|---|---|---|---|---|---|---|
| x11 | ✔ | ✔ | ✔ | ✔ | ✔ | ✘ |
| wtype | ✘ | ✔ | ✘ | ✔ | ✔ | ✘ |
| ydotool | ✘ | ✘（仅 ASCII） | ✘ | ✔ | ✔ | ✔（需 ydotoold） |

auto 选择：真 X11 会话（`XDG_SESSION_TYPE=x11`，或 `DISPLAY` 且无 `WAYLAND_DISPLAY`）→ `x11`；Wayland → `wtype` → `ydotool`；`XDG_CURRENT_DESKTOP` 含 GNOME 时反序（ydotool 优先）。

`--list-backends` 输出固定表头 `后端      可用  探测依据`，末尾两行 `当前会话: ...` / `auto 将选择: ...`（`format_backends()`）。

1. **一个事实只有一个 owner**：想写一条事实，先查上表；不属于你的文件就改成链接 + 一句上下文。

## 3. 单一事实来源与防漂移

### 3.1 问题陈述

`--backend` 这一批 flag 的事实现在存在于 **5 处**：`build_parser()`、`--help`、README.md 表、README.en.md 表、CHANGELOG。02 起 review 已两次报"文档与代码不一致"（02.3）——靠人记同步是不可持续的。

### 3.2 方案：一个生成器 + 一个测试文件（不引入依赖、不改运行时）

#### (a) `tools/gen_cli_docs.py`（新增，~90 行，纯标准库）

职责：
1. `import autopaste`（**安全**：基线里 libX11 是惰性加载，import 不碰 X，已由 `test_help_works_without_libx11` 保证）。
2. 遍历 `build_parser()._get_optional_actions()` + `_get_positional_actions()`，生成 markdown 表：

```python
def flag_rows(parser):
    for a in parser._get_positional_actions() + parser._get_optional_actions():
        if isinstance(a, argparse._HelpAction):
            continue
        names = ", ".join(f"`{s}`" for s in (a.option_strings or [a.dest]))
        # 取值列：choices / type / default；flag 类写 "—"
        ...
        yield names, value_col, a.help
```

   列：`参数 | 取值 / 默认 | 说明`。`--version` 这类 `action="version"` 的 action 也要列出（否则文档缺项）。
3. 读 `docs/cli.md`，把 `<!-- BEGIN AUTO:flags -->` 与 `<!-- END AUTO:flags -->` 之间的内容整体替换；`--check` 模式只比较、不写，有差异打印 diff 摘要并 `exit 1`。
4. 同一个脚本生成 `docs/backends.md` 的 `<!-- BEGIN AUTO:matrix -->` 区块：用

```python
import types
for cls, name in ((autopaste.X11Backend, "x11"), (autopaste.WtypeBackend, "wtype"),
                  (autopaste.YdotoolBackend, "ydotool")):
    caps = cls.capabilities(types.SimpleNamespace(name=name))   # 方法体只用 self.name
```

   → 不需要实例化（X11 实例化会连 Display）。`capabilities()` 若将来开始读实例状态，这里会立刻炸，属于"想要的失败"。
5. **自校验**：生成完断言每个 flag 都出现在 `parser.format_help()` 里（`_actions` 是 argparse 私有 API，用公开的 `format_help()` 兜底校验，把私有 API 的风险限制在"生成"而不是"校验"）。

#### (c) CI 改动（`.github/workflows/ci.yml`，`check` job，+6 行）

```yaml
      - name: 文档与代码一致
        run: |
          python tools/gen_cli_docs.py --check
          python -m unittest tests.test_docs -v
```

同时把已有的"校验文档中引用的文件都存在"循环里加上 `docs/README.md docs/usage.md docs/cli.md docs/backends.md docs/design.md CONTRIBUTING.md tools/gen_cli_docs.py`。

### 3.3 刻意不做的三件事

- **不自动生成 README 的能力矩阵**：4 行 × 4 列，人读的抽象层次和 `capabilities()` 的 7 个布尔不是一一对应；用 `test_all_docs_linked` + 人工 review 兜住。
- **不从 `--help` 的 `format_help()` 文本反解析生成表**：`RawDescriptionHelpFormatter` 会按宽度换行，正则解析比私有 `_actions` 脆得多。
- **不做 doc 覆盖率门禁**（"每个 flag 必须在 usage.md 出现"）：会逼着写废话。

### 5.1 PyPI 名核对（05 不阻塞发布，先核对再决定）

### 5.2 Release 附件：要

wheel + sdist 都挂。理由：pipx/pip 用户的离线安装路径、以及"GitHub 打包 ≠ PyPI 发布"时唯一的可验证安装物；成本只有 `pip wheel` 一行（sdist 需要 `python -m build`，若无 `build` 就用 `python setup.py sdist` 的现代等价：`pip download . --no-deps --no-binary :all: -d dist`，可接受丢弃）。

### 5.3 README 首屏

必须在前 10 行内出现：
1. 它是什么（敲键注入，不是剪贴板）；
2. **和 xdotool 的区别**（零 Python 依赖、默认安全闸门、Wayland 走 wtype/ydotool、不需要常驻）；
3. **加粗安全警告**（"等同于替你敲键盘；多行文本打进终端 = 逐行执行；只在你能看到屏幕时用"）。

差异表（完整版放 `docs/design.md`，README 只留一句话）：

| | AutoPaste | xdotool | 剪贴板粘贴 |
|---|---|---|---|
| 依赖 | 零 Python 依赖（X11 直接 ctypes） | 需安装 + libxdo | 需 xclip/wl-copy 或终端支持 |
| 内容通道 | 直接生成按键事件，不碰剪贴板 | 同 | 全局剪贴板（会被管理器留存） |
| Wayland | wtype / ydotool（外部工具，固定 argv） | 仅 X11/XWayland | 视工具 |
| 内置闸门 | 拒 root、拒控制字符、多行确认、`--dry-run` | 无 | 无 |
| 失败模式 | 焦点被抢 → 敲错窗口（因此有倒计时目标提示） | 同 | 粘贴目标由用户保证 |
