## Conclusion

抽象方向正确：`X11Backend` 是旧 `Typer` 方法体的整块搬迁，注入顺序、
`finally` 释放修饰键、remap→tap→restore、`countdown`、`--dry-run` 的
XTEST 语义均与 `9c6c9a3` 一致，X11 行为未变（唯一差异是删掉了
`DISPLAY` 预检查，属于诊断信息变化，不影响注入路径）。lazy dlopen 实现干净，
`import`/`--help`/`--list-backends` 不会因缺 X 库崩溃。
但新增的 ydotool 调用漏掉 `-e 0`：ydotool 对命令行文本**默认开启反斜杠转义**，
`\n`/`\t`/`\xNN` 会被解码，这既静默改写用户文本，也**绕过了
`validate_payload` 的控制字符拦截和 Wayland「多行必确认」两道安全闸门**，
属于阻塞级缺陷。另有 wtype 的 `super`/`meta` 修饰键名不被 wtype 接受、
GNOME 下 `auto` 仍首选必然失败的 wtype（且无运行期回退）两处功能性 major。
结论 **issues**。

## 逐项结论

### 1. X11 行为未变：是（注入路径逐行一致）

对照 `9c6c9a3` 的 `Typer`（旧 229–402 行）与新 `X11Backend`
（`autopaste.py:309-495`）：

- `_tap` / `_remap` / `_restore_keymap` / `type_text` / `type_char` /
  `_unicode` / `press` 方法体逐字符相同，仅类名变化，没有重排事件顺序，
  也没有移动 `time.sleep` 的位置。
- `press()` 的 `try/finally` 仍按 `reversed(pressed)` 释放修饰键
  （`autopaste.py:461-471`）；`_unicode()` 的 `finally: _restore_keymap()`
  仍在（`:419-426`）；`close()` 仍先 restore 再 `XCloseDisplay`（`:484-495`）。
- `countdown()` 改为 `target_label(typer)`（`:1070-1076`），X11 下等价于
  旧的 `describe_window(focused_window(typer.dpy))`；`seconds <= 0` 的早退
  时序也未变（旧代码同样先算目标再早退）。
- `--dry-run` 对 x11 只多一行 `后端     : x11`（`:1465-1467`），
  `needs_remap=True` 仍走 `resolvable()` 分支（`:1478-1482`），其余输出行
  与旧版一致。
- 例外（不在注入路径上）：旧 `main()` 的"未设置 DISPLAY 直接退 2"
  被删除（见 m1）；`focused_window()` 增加 `_require_x11()` 守卫
  （`:195-197`），这是 lazy load 的必要防护，不是行为回归。
- 回归测试有效：`test_typer.py` 的
  `test_unicode_restores_even_when_tap_fails`（:78）、
  `test_shift_released_when_tap_raises`（:95）、
  `test_modifiers_released_when_tap_raises`（:124）以及
  `test_backends.py::X11RegressionTests` 的真实假 X11 事件序列，
  删掉任一处 `finally` 都会失败。

### 2. lazy dlopen：正确

- 模块级只剩 `x11 = None / xtst = None`（`:81-82`），无 import 期 `CDLL`；
  `_load_x11()` 幂等，且**只在两个 CDLL 都成功后才一起赋值**
  （`:100-141`），不会出现 x11 已设而 xtst 为 None 的半初始化状态。
- 失败信息可读：包了 `OSError` 并提示改用 wtype/ydotool（`:103-107`）；
  `XOpenDisplay` 失败信息带 `DISPLAY=` 值（`:316-319`）。
- "第一次调用才炸"的路径不存在：所有生产路径先构造 `X11Backend`
  （构造时 `_load_x11`）；`focused_window()` 在未加载时抛
  `BackendUnavailable`，不会把 `None` 传给 ctypes（`:144-148`）。
- `--list-backends` 在 `format_backends()` 里自行 try `_load_x11`
  （`:1351-1364`），无 X 环境安全。`--help/--version` 在
  `main()` 之前由 argparse 处理，`--version` 也不会 dlopen。
- 小问题：`format_backends` 把 XWayland（`DISPLAY` 存在但
  `XDG_SESSION_TYPE=wayland`）的 x11 标成"可用=是"，且库缺失但
  `XDG_SESSION_TYPE=x11` 时仍打印"auto 将选择: x11"，与"不可用"自相矛盾（m5）。

### 3. wtype：argv/分片/配对基本正确，修饰键名有缺陷

- `subprocess.run` 走唯一出口 `_run()`（`:499-510`），argv 为 list，
  未传 `shell`（默认 False），`check=False` 由后端解析返回码；
  `type_text` 用 `["--", chunk]` 防止文本被当成选项（`:576-580`）。
  无 shell 注入面，符合 SECURITY 的"固定 argv、不经 shell"。
- 分片 `_chunks()` 按 `len(ch.encode("utf-8"))` 累加，超限时先 flush
  （`:520-532`），不会切半个字符。`test_chunks_never_split_multibyte_chars`
  （`test_backends.py:205`）用 `32767 a + 中…` 覆盖了"3 字节字符恰好跨
  32768 边界"，断言首片 32767、次片以 `中` 开头，结论正确。
- `-M/-k/-m` 成对：先全部 `-M`、`-k`、再 `reversed(mods)` 的 `-m`
  （`:589-595`）。wtype 在 `parse_args` 阶段就会对非法修饰键 `fail()`
  退出（尚未创建虚拟键盘、未按任何键），因此参数错误不会留下按住的修饰键；
  运行期 Ctrl-C 由前台进程组同时打断 wtype，合成器在 destroy 时清空键盘，
  没有发现"修饰键卡住"路径。注意这是"依赖单进程 + 工具退出即清理"的保证，
  不是 Python `finally` 保证（SECURITY #9 的措辞需要区分，见 m2）。
- 返回码/stderr：非 0 取 stderr 最后一行截 200 字符抛 `BackendError`，
  协议特征追加 GNOME 提示（`:564-573`）；`FileNotFoundError` 转
  `BackendUnavailable`。可用。
- **缺陷**：`MODIFIERS` 的 `super`/`meta` 被原样传给 `-M`，而 wtype 只认
  `shift/capslock/ctrl/logo/win/alt/altgr/mod1..4`（上游 `mod_names[]`），
  `-M super` 会 `fail("Invalid modifier name 'super'")`。README 明确宣传
  `super`/`win` 两个别名，`-k super+l` 在 wtype 上直接失败，且错误只是通用
  `BackendError`。`win`/`ctrl`/`shift`/`alt` 可用（M1）。

### 4. ydotool：能力暴露合格，但文本转义处理是阻塞缺陷

- 非 ASCII：`type_text` 在分片前显式检查 `ord(ch) > 0x7E` 并 `Abort`，
  消息给出 wtype/替代建议（`:716-726`），不会静默丢字；`capabilities()`
  也如实给出 `unicode=False`（`:745-749`），不是静默失败。
- socket 探测顺序 `YDOTOOL_SOCKET → $XDG_RUNTIME_DIR/.ydotool_socket →
  /tmp/.ydotool_socket`（`:636-649`），与 ydotool 自身 `main()` 的顺序一致；
  缺 socket 的报错准确指出 ydotoold/权限。
- evdev 表抽查正确：a=30、z=44、0=11、space=57、enter=28、up=103/left=105/
  right=106/down=108、ctrl=29/shift=42/alt=56/super=125，未发现明显错误；
  未知键 `_keycode()` 直接 `Abort` 而非猜码（`:707-713`）。
- **B1（阻塞）**：`ydotool type` 对命令行参数**默认开启 escape**
  （上游 `tool_type.c`：无 `-f` 时 `enable_escape = 1`；`escape()` 解码
  `\n`、`\t`、`\xNN`、`\\`，未知转义直接丢弃）。本实现对 argv 只加了
  `--`，没有加 `-e 0`（`:725-726`）。后果：
  1. 文本被静默改写：`C:\new\table` → 换行/Tab + 丢字符；
  2. `validate_payload` 看到的只是普通字符 `\` `x` `1` `b`，ydotool 却会
     生成 ESC/换行，**绕过控制字符拦截**（SECURITY #3）；
  3. 文本里没有真实换行，所以 `multiline_risk()` 不触发确认，
     而 ydotool 把它变成换行在终端里逐行执行，**绕过 Wayland 多行确认**
     （SECURITY #4，这是本任务自己新增的收紧项）；
  4. 文本以单个 `\` 结尾时，上游 `escape()` 的状态机在 NUL 之后继续读，
     存在越界读（上游 bug，但由本调用触发）。
  这不是"上游偶发"，而是本后端每次 `type` 的固定行为。修复：argv 加
  `-e 0`（`["type", *delay, "-e", "0", "--", chunk]`），并补一条
  "argv 含 `-e 0`、反斜杠文本原样传递"的测试。
- 次要：evdev 表缺 `backslash`(43) 等符号键，`-k backslash` 会报不支持；
  `asterisk` 映射到 KP 的 55 而非 shift+8（m6）。

### 5. 测试强度：新增用例总体是真断言，但有覆盖盲区

- 新增用例（`test_backends.py` 约 56 条）大多断言**精确 argv 或事件序列**，
  不是只看返回码：wtype 的 `test_type_text_argv`、`test_combo_argv_ctrl_shift_v`，
  ydotool 的 `test_combo_uses_evdev_codes`、`test_type_argv`，X11 回归的
  事件序列都属于"实现改错会红"。
- 盲区（会导致假绿）：
  - `test_type_argv` 把**错误的** argv 当作期望固化下来
    （`["ydotool","type","--key-delay","8","--","hello"]` 缺 `-e 0`），
    所以 B1 完全测不出来；也没有任何"反斜杠文本"用例。
  - 没有 `super` 修饰键的 wtype 用例，也没有 GNOME auto 用例。
  - `test_help_works_without_libx11`（:392）只调用 `build_parser()`，
    从未触发 dlopen，证明不了 lazy load；`--list-backends` 在 CDLL 抛
    `OSError` 下的路径没有测试。
  - `test_run_seam_never_uses_shell` 有效（断言无 `shell` 且 `check=False`），
    是本次最有价值的负面断言。
- `test_cli.py` 把"无 DISPLAY 报错"改成"无后端退 2"（:63-73）：
  **退出码语义保留**（仍是 2，且给出安装提示），但原来针对 X11 用户的
  `DISPLAY` 专属诊断不再被覆盖，同时代码也确实删掉了该诊断（m1）。
  判定为**削弱**（消息层），不是行为回归。

### 6. 安全默认未放宽：除 B1 外均保留

逐条对照 `SECURITY.md`：

- FIFO/设备：`check_regular_file` 未改（`:260-268`），仍只接受普通文件。
- 输入上限：1 MiB 未改；wtype/ydotool 的 32 KiB 分片是下限约束，不是放宽。
- 目标可视化：X11 仍显示 WM_CLASS；Wayland 诚实降级为"看不到焦点"

## Findings

### Blocker

- **B1 ydotool `type` 未关闭转义，绕过控制字符/多行两道闸门**
  `autopaste.py:716-726`（`type_text`）→ `:687-705`（`_exec`）。
  上游 ydotool 对命令行文本默认 `enable_escape=1`，`\n`/`\t`/`\xNN` 被解码。
  复现：`autopaste --backend ydotool 'echo a\nrm -rf ~'`（字面反斜杠）
  → `multiline_risk` 看不到换行、不确认，ydotool 却敲出换行。
  修：`-e 0` + argv 断言测试（含反斜杠/末尾反斜杠用例）。

### Major

- **M1 wtype 修饰键 `super`/`meta` 不可用**
  `autopaste.py:582-595` 原样把 `parse_combo()` 的 token 传给 `-M`，
  而 wtype 只认 `logo`/`win`（`MODIFIERS` 在 `:162-166` 宣传 `super`/`win`/`meta`）。
  `--backend wtype -k super+l` 必然失败；应做 wtype 侧映射表
  （ctrl/shift/alt→同名，super/win/meta→`logo` 或 `win`）。
- **M2 GNOME 下 `auto` 必选 wtype，且无运行期回退**
  `choose_backend()`（`:786-802`）只按 wtype→ydotool 顺序，
  忽略 `XDG_CURRENT_DESKTOP`；README 安装命令同时装二者（README:36-42），
  在 mutter（不支持 virtual-keyboard）上 `auto` 100% 失败。探索计划 §3.2
  要求的"GNOME 反序 + auto 下 wtype 协议失败转 ydotool"均未实现。
  错误提示能救（"请改用 --backend ydotool"），但 headline 的 `auto`
  在最常见的 Wayland 桌面上开箱不可用；且没有对应测试。

### Minor

- **m1 无 DISPLAY 的诊断退化**：旧版 `main()` 直接提示
  "未设置 DISPLAY"；现在 `auto` 落到 `unknown`，`_missing_hint()`
  （`:772-783`）只讲 Wayland 工具安装，X11 用户会被误导；且
  `test_cli.py` 的替换测试不再守护该消息。退出码 2 保留。
- **m2 SECURITY #9 的方法名/适用范围失真**：`Typer._tap/press/close` 已不存在；
  外部后端的修饰键释放与 keymap 还原不适用。
- **m3 "所有多行一律确认"与 REPL 不符**（SECURITY #4、CHANGELOG、
  README:121）：REPL 只警告（`:1218`）。
- **m4 README `-y` 语义未覆盖 Wayland 全多行确认**（README:69）。
- **m5 `--list-backends` 的 x11 可用性判断只看库+DISPLAY**：XWayland 下
  标"是"、库缺失但 `XDG_SESSION_TYPE=x11` 时仍打印"auto 将选择: x11"
  （`:1358-1365`、`:1393-1398`），与"不可用"矛盾。
- **m6 evdev 表缺 `backslash`(43) 等符号键；`asterisk` 指向 KP(55)**
  （`:604-633`），组合键会报"不支持"或敲出键区符号。
- **m7 `parse_combo` 未真正共享**：X11 `press()` 仍保留一份内联解析
  （`:428-471`），与 `:897-906` 存在漂移风险；CHANGELOG 措辞超前。
- **m8 惰性加载的可测性**：`test_help_works_without_libx11` 不触发
  `_load_x11`；建议加 `main(["--list-backends"])` + `CDLL` 抛 `OSError`
  的测试，否则该回归点无守护（`test_backends.py:392`）。
- **m9 `_run(text=True)` 依赖 locale 解码 stderr**：非 UTF-8 locale 下
  读取外部工具错误可能抛 `UnicodeDecodeError` 而不是可读提示；
  建议显式 `encoding="utf-8", errors="replace"`。

### Nit

- **n1** `capabilities()` 的 `can_paste_mode`/`per_char_delay` 恒为
  False/未消费（`:296-300`、`:597-601`），属于尚不存在的契约，建议注释
  或删掉，避免 UI 依赖空字段。
- **n2** `--list-backends` 在 root 检查之前执行（`:1406-1408`）：
  只读诊断，但顺序上可记录为有意例外。
- **n3** `_delay_ms` 把 `delay>0` 且四舍五入为 0 的情况抬到 1ms，
  文档未写"Wayland 后端精度 1ms"，属于可接受差异。

## 架构影响说明

- 单文件（1544 行）仍是合适的：`Typer` 只做转发，注入逻辑各自独立，
  共享层只有 `SPECIAL/MODIFIERS/parse_combo/target_label/multiline_risk`，
  抽象没有变成"第二个程序"。
- 但是**测试接缝变成了模块级可变全局**：`tests/` 仍靠
  `mock.patch.object(autopaste, "x11"/"xtst")`，而 `_load_x11()` 的幂等
  早退依赖 `x11 is not None`；未来若把后端拆成子模块，这两个全局
  （以及 `Typer` 无 `.dpy` 的决定）会是最先断裂的契约，拆分时要同步改测试接缝。
- 新增的外部进程边界（`_run` + 固定 argv + 无 shell）现在是安全边界：
  任何"把用户文本交给工具前需要转义/关闭转义"的语义都必须由后端自己保证，
  不能指望 `validate_payload`（B1 正是这个边界漏了）。
